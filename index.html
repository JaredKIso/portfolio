Case study · Tek Knowledge

A 53.5 million-file backlog that wasn't index corruption

A state electric-grid operator's Carbon Black App Control server had a backup backlog of 53.5M files. The earlier diagnosis said the database index was corrupt. The logs said otherwise.

  1. report

    The problem

    Backups had stalled at critical-infrastructure scale. A prior diagnosis blamed index corruption, which would have meant a long, risky rebuild.

  2. manage_search

    The diagnosis

    Reading the SQL Server logs directly showed the service account was missing 7 permissions, and maintenance flags were stuck. The index was fine.

  3. build

    The fix

    Grant the missing permissions, clear the stuck flags, and let the backlog drain in a single maintenance window.

  4. trending_down

    The result

    53.5M → <1M

    Backlog under one million files after one window, with no rebuild.
